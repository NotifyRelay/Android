# 测试策略

本文是本仓库的测试层级、证据选择与执行拓扑。构建口径与警告基线见[构建与验证](构建与验证.md)，缺陷类别规则见[缺陷类别规则页](缺陷类别规则.md)。

<a id="tiers"></a>

## 测试层级

| 层 | 位置 | 覆盖对象 |
|---|---|---|
| 文档门禁 | `scripts/` | 文档结构、链接、预算、Agent Note 契约、技能调用元数据、重复代码 |
| 单元测试 | `app/src/test`、`data/src/commonTest`、`checkupdata/src/jvmTest`、`desktop/src/jvmTest`、`nativecore/notify-relay-core/src`（`cargo test --lib`） | 纯函数与协议序列化：文本切分、通知过滤判定、远端过滤报文、scrcpy 参数串、版本比较、剪贴板回包解码与防循环判定 |
| 构建验证 | `./gradlew assembleDebug`、`compileDebugKotlin` | 编译面与警告基线 |

设备侧行为（通知转发、超级岛渲染、桌面端窗口与叠加层）没有自动化测试层，其证据来自真机复现与日志。

<a id="evidence-selection"></a>

## 证据选择

按改动面取最小充分证据，不反射性地跑全量；CI 拥有穷尽矩阵。

| 改动 | 最小证据 |
|---|---|
| 文档、Agent Note、目录页 | `pnpm run test:docs` |
| Kotlin 源码 | 对应模块 `compileDebugKotlin` 加相关单元测试，加全仓 `ktlintCheck` |
| 门禁脚本本身 | 该脚本的单元测试，加上一次故意违规的负向验证 |
| 指令文件（`AGENTS.md`、技能） | `pnpm run verify-all` |
| 原生代码 | `assembleDebug` 与真机复现，加 `cargo test`、`cargo fmt --check` 与 `cargo clippy` |

<a id="execution-topology"></a>

## 执行拓扑

文档门禁由 `pnpm run verify-all` 并发运行八道门禁，挂在 Gradle `verifyDocs` 任务上，随 `./gradlew check` 执行，并在 `.githooks/pre-push` 里先于 `ktlintFormat` 运行；PR 工作流的 `docs` job 先于构建失败即中止。Gradle 侧的 `verifyDocs` 只声明 `Docs/`、`.agents/`、`scripts/`、`AGENTS.md` 与锁文件为 inputs，输入未变时增量跳过。

单元测试归属所在模块，随该模块的 `check` 执行；子模块有自己的测试与构建配置，本仓库不代为运行。

<a id="resource-ownership"></a>

## 资源归属

`node_modules/` 属于文档门禁依赖，由 `pnpm install` 装在仓库根，不入库。原生产物 `nativecore/notify-relay-core/build` 体积大，多工作树用目录联接复用，构建全局串行；详见[构建与验证](构建与验证.md#environment)。

测试用的临时文件写在系统临时目录，不进仓库；需要留存的证据以日志片段形式进入复盘或提交说明。

<a id="gate-self-proof"></a>

## 门禁自证

新增门禁必须自证：写一个非法用例，看它变红，再回退。只证明它能通过，等于没证明它有用。
