# 事故复盘

事故复盘是唯一承载亲历叙事的文档层级：按时间记录证据、因果链、影响与预防。缺陷类别规则见[缺陷类别规则页](缺陷类别规则.md)，决策理由见 [Agent Note](../.agents/notes/README.md)。

<a id="scope"></a>

## 收录范围

一篇事故复盘以一次事故为界，覆盖用户可观察的中断、数据损坏、错误发布与安全回归。修复提交本身不足以代替复盘：提交记录「改了什么」，复盘记录「为什么当时的机制没能拦住」。

局部界面调整、机械重构与未上线的缺陷不进本层；它们属于对应提交。

<a id="structure"></a>

## 结构

按事故顺序记录证据，不按教学顺序：

1. **影响。** 谁在什么条件下受影响，持续多久，有无数据损失。
2. **时间线。** 以带时区的时刻串起观测、处置与恢复；只写可核对的证据。
3. **因果链。** 从触发条件到可观察后果，指出哪一层的保证失效。
4. **遏制与恢复。** 实际采取的动作，以及恢复后仍然成立的保证。
5. **预防。** 每一项对应可执行的改动：新增门禁、收窄捕获、补测试或改协议；没有对应改动的预防项不写入。

<a id="naming"></a>

## 命名与归档

文件名采用 `yyyy-mm-dd-<事故主题>.md`，与目录内的其他复盘并列。事故已在机制层解决且不再指导未来判断时移入归档；归档记录是冻结历史，不改写。
