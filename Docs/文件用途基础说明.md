`:core` 的 Gradle 模块名与源码目录不同名，`settings.gradle.kts` 中以
`project(":core").projectDir = file("nativecore")` 重定向。

LSPosed 模块位于平级独立仓库 `NotifyRelay-LSP`（独立 APK，不参与本仓库构建）。

子模块配置（`.gitmodules`）：

- `checkupdata` → `git@github.com:xzy-nine-common/checkupdata-android.git`（branch `main`）
- `scrcpy` → `git@github.com:xzy-nine/ScrcpyForAndroid.git`（branch `library`）
- `nativecore/notify-relay-core` → `https://github.com/NotifyRelay/core.git`（branch `main`）

根 `build.gradle.kts` 对 `checkupdata`/`scrcpy` 不应用 ktlint。

### 1.3 模块依赖关系

```
:app ──┬── :shared ────┬── :base（基础设施层）
       │               ├── :domain（领域模型与端口契约）
       │               └── :checkupdata（更新检查）
       ├── :domain ──────────── :base
       ├── :data ────────────┬── :base
       │                     └── :domain
       ├── :core ────────────┬── :base（Rust 核心，源码目录 nativecore/）
       │                     └── :domain
       ├── :superislandui ───┬── :base
       │                     └── :data
       ├── :checkupdata        （无内部依赖）
       └── :scrcpy ──────────┬── :base
                             └── :data
:desktop ──┬── :shared
           ├── :domain
           ├── :data
           ├── :core
           └── :base
```

`:base` 为最底层（无内部依赖）；`:domain` 只依赖 `:base`；`:data` 依赖 `:base` 与 `:domain`；`:shared` 依赖 `:base`、`:domain` 与 `:checkupdata`。

`buildSrc/` 为 Gradle 构建辅助工程。Rust 侧代码位于 `nativecore/notify-relay-core`。

### 3.5 `:checkupdata`

KMP 库，目标为 `android` 与 `jvm`。全部业务逻辑位于 commonMain；平台差异经 `internal expect` 声明在
androidMain/jvmMain 各自实现，并经同名工厂函数暴露给调用方。

| 源集 | 内容 |
|---|---|
| commonMain | `CheckUpdateManager`、`GitHubApiClient`/`GitHubApiService`、`UpdateCache`、`SystemDownloader`、`CheckUpdateConfig`/`ReleaseInfo`/`UpdateResult`、`VersionComparator`/`VersionRule`、`internal/Platform.kt`（平台 seam 声明）、`internal/JsonSupport.kt` |
| androidMain | `Platform.android.kt`（IO 调度器、时间、OkHttp 请求、文件读写）、`AndroidDownloadStarter`（系统 DownloadManager）、`PlatformFactories.kt`（`CheckUpdateManager(context)`、`SystemDownloader(context)`） |
| jvmMain | `Platform.jvm.kt`、`JvmDownloadStarter`（同步下载到缓存目录）、`PlatformFactories.kt`（`CheckUpdateManager(cacheRootDir)`、`SystemDownloader(cacheRootDir)`） |

| 类 | 职责 |
|---|---|
| `CheckUpdateManager` | 更新检查入口，编排请求/缓存/下载（构造器为 internal，平台侧经同名工厂函数构造） |
| `GitHubApiClient` / `GitHubApiService` | GitHub Release API 客户端与接口定义 |
| `UpdateCache` | 更新检查结果缓存（`saveCache`/`loadCache`/`clearCache`，均接收缓存根目录） |

### 3.6 `:core`

Kotlin 绑定由 `:core:uniffiBindgen`（`gobley-uniffi-bindgen`）从 `cargo-ndk` 产出的 `.so` 生成，
产出包为 `com.xzyht.notifyrelay.core.ffi`，生成物位于 `nativecore/build/generated/uniffi-kmp`，不入版本库。

模块为 KMP 库（android 单目标）。`uniffi.kmp.toml` 以 `kotlin_multiplatform = true` 产出双源集绑定：
commonMain 为 `expect` 声明，androidMain 为 `actual` 实现（JNA 调用 `.so`）。两个目录分别注册到对应源集的 kotlin 目录。

| 源集 | 内容 |
|---|---|
| commonMain | UniFFI 绑定的 `expect` 声明（`Core`、`CoreCallbacks`、顶层函数）；`NativeCore` 门面；`PlatformMediaProjection` 的 expect 声明 |
| androidMain | UniFFI 绑定的 `actual` 实现（JNA）；`PlatformMediaProjection` 的 actual typealias |

`NativeCore`（object）是 `:core` 的对外门面，位于 commonMain，覆盖：

- 会话：`createContext()`, `isReady()`, `exportState()`, `importState()`, `encryptLocalState()`, `decryptLocalState()`, `deserializeLocalState()`
- 加密：`generateKeypair()`, `getPublicKey()`, `hasKeypair()`, `deriveSharedSecret()`, `migrateSharedSecret()`, `deriveFtpCredentials()`, `derivePasswordHash()`, `generateRandomPassword()`
- 设备：`getLocalUuid()`, `renameDevice()`, `getDeviceList()`, `removeDevice()`, `removeDeviceSession()`
- 连接/配对：`periodicBroadcast()`, `sendHandshake()`, `connectDevice()`, `sendPairingInit()`, `sendPairingResp()`, `sendAccept()`, `sendReject()`, `generatePairingCode()`, `clearPairingCode()`
- 消息：`enqueueMessage()`, `computeFeatureId()`, `dedup()`, `contentDedup()`, `shouldDeduplicate()`

- 同步：`clipboardOnChanged()`, `clipboardOnReceived()`, `appSyncPrepareIconRequest()`, `appSyncRequestIcons()`, `appSyncClearIconPending()`, `appSyncParseIconResponse()`, `appSyncBuildApplistRequest()`, `appSyncParseApplistResponse()`
- 状态推送：`pushSuperislandState()`, `pushMediaState()`, `onNetworkChanged()`, `getLocalIp()`, `updateHeartbeatSchedulerParams()`
- 回调：`setCallbacks(CoreCallbacks)`（配对/数据/设备事件/状态查询/音频/日志合一）

`NativeCore` 不持有上下文句柄；上下文由 UniFFI 生成的 `Core` 对象单一持有。

## 四、构建相关

- 版本号来自根目录 `version.properties`（由 `update.yml` 在 push 到 `main` 时按 conventional commits 语义回写）；CI 可用 `-PversionName/-PversionCode` 或环境变量 `VERSION_NAME/VERSION_CODE` 覆盖。
- `:app` 在 release 构建时启用 ABI splits（`arm64-v8a`、`x86_64` + universal），debug 仅生成 universal APK。
- `preBuild` 依赖 `generatePermissionNotes`：解析 `AndroidManifest.xml` 中 `<uses-permission>` 上方注释，生成 `res/raw/permission_notes.txt`，供协议页（`GuideAgreementPage`）展示权限用途。**权限用途只需维护 Manifest 注释，不要在 Kotlin 中手抄**。
- `:app` 声明 `aidl = true`、`buildConfig = true`、Compose 开启。LSPosed 入口声明（`META-INF/xposed/*`）不合并进主 APK。
- ktlint 应用于除 `checkupdata`、`scrcpy` 之外的所有模块。
- `:checkupdata` 的 `commonMain` 以 `api` 声明 `kotlinx-serialization-json`（其类型出现在公开签名中）；`androidMain`/`jvmMain` 各自以 `implementation` 声明 `okhttp`。
- `:core` 为 KMP 库（android + jvm 双目标）：`uniffiBindgen` 以 KMP 配置产出双源集绑定，`hostRustBuild` 为本机（jvm/桌面）产出动态库；`rustBuild`/`uniffiBindgen` 挂在 `compileAndroidMain`/`androidPreBuild`/`compileKotlinJvm`（KMP 库插件不创建 `preBuild`）；Android `.so` 经 `androidComponents.onVariants` 注册为 jniLibs 目录。
- `:core` 需要 `-Xexpect-actual-classes`：UniFFI 生成物以 `expect/actual class` 承载 `Core`（Kotlin 官方 Beta 特性）。
