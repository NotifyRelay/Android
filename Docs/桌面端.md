# 桌面端

本文是 JVM 桌面端（`:desktop`）的当前契约：窗口与托盘、主题、配对、电量、打包与叠加层。模块结构见[模块结构](模块结构.md)，构建口径见[构建与验证](构建与验证.md)。

<a id="window-and-tray"></a>

## 窗口与托盘

关闭按钮隐藏到托盘，由 `DesktopWindowController` 负责隐藏与显示；托盘左键显示窗口、右键请求菜单。退出只经托盘菜单。系统托盘不可用时关闭即退出。

托盘菜单是 Compose 弹层：`Main.kt` 的 `TrayMenu` 用 Miuix `Card` 加菜单项与分割线，尺寸 168×84dp。

<a id="theme"></a>

## 主题

`DesktopThemePort` 把索引持久化到 `Storage` 的 `theme_base_index`：0 跟随系统、1 浅色、2 深色。主窗口与托盘菜单统一用 `NotifyRelayTheme`。

<a id="pairing"></a>

## 配对

`ProvideDesktopPairingDependencies(deviceManager.handshakeWaiters)` 注入 `PairingDependencies`：核心 `NativePairingCorePort`、电量 `BatteryLevel.signedPercent()`、平台标识 `pc`。

握手等待器必须与 core 回调侧同实例。

`PAIRING_RESP` 首段语义是发送方（响应方）本机 uuid。`sendPairingResp` 一律传本机 uuid，与 Windows 端 `localDeviceId` 同口径。

<a id="battery"></a>

## 电量

`BatteryLevel` 提供 `percent()`（界面，无符号）与 `signedPercent()`（上报 core，正为充电、负为放电）。

`PowerStatusMonitor` 经 JNA `powrprof.PowerSettingRegisterNotification` 监听电池余量与交流电来源，变化时刷新可观察快照并 `updateHeartbeatSchedulerParams`。

<a id="clipboard"></a>

## 剪贴板同步

剪贴板文本在平台与 Rust core 之间的唯一口径是 `LF`：写回系统剪贴板前把 `CRLF` 归一为 `LF`，采集时再归一一遍（该归一自身幂等），Rust 在收发两侧也做同一次归一；图片以 PNG 的 Base64 传输。平台侧不持有任何同步状态：本机复制与远端回灌的区分、重复内容是否跳过、频率限制与 2MB 阈值全在 Rust core 的 `clipboardOnChanged` 内闭环。

防循环的做法是：Rust 收到远端内容时登记其内容与类型，平台把这批内容写回系统剪贴板又触发自身监听时，回灌在 1000ms 窗口内被忽略。判定按归一化后的内容比较，不要求类型一致；图片另有兜底——剪贴板中的图片是平台重编码后的 PNG，与线上 Base64 不同，内容不可比，按类型与时间窗判定。故平台交给 Rust 的必须是回读时的那一个字符串：回包按 JSON 语法解码，解码失败放弃写入并记警告；口径不一致时内容相等前提不成立，回灌会被当成新的本机复制再次发出。

文本经 `Win32Clipboard` 直写 `CF_UNICODETEXT`，绕开 AWT 把换行改写为 `CRLF` 的行为；非 Windows 回落 AWT。

<a id="encoding"></a>

## 控制台编码

`desktop/build.gradle.kts` 为 `JavaExec` 与 `Test` 设 `stdout.encoding`、`stderr.encoding` 为 UTF-8。JDK 18+ 下 `file.encoding` 不再决定控制台编码。

<a id="packaging"></a>

## 打包

用 `gradlew :desktop:runDistributable` 运行打包产物；`run` 每次都要构建且会掩盖打包产物的问题。

jpackage 裁剪运行时默认不含 `java.net.http`。用 `HttpClient` 时必须在 `compose.desktop.application.nativeDistributions` 里 `modules("java.net.http")`，否则只在打包产物运行时报 `NoClassDefFoundError`。核对方式：读 `desktop/build/compose/binaries/main/app/NotifyRelay/runtime/release` 的 `MODULES=` 行。

打包产物不显示控制台：`nativeDistributions.windows.console` 为 `false`。核对方式是读 PE 头 `OptionalHeader.Subsystem`（PE32+ 偏移 `opt + 0x44`），`3` 为 CONSOLE、`2` 为 GUI。

<a id="overlay"></a>

## 叠加层

叠加层是进程内无边框透明窗口，由 `DesktopOverlayWindow` 用 Compose 直接绘制，样式为 `WS_EX_LAYERED|TRANSPARENT|NOACTIVATE|TOOLWINDOW`。不经伴生进程与位图传输。

媒体卡展开态复用 `:superislandui` 的 `MediaIslandCompose`。超时收起为摘要胶囊，换曲重新展开；换曲与首次出现属于自动展开，不显示播放/暂停、上一首、下一首按钮，仅用户点击胶囊展开时才显示（`interactiveEnabled` 关闭时一律不显示）。

媒体卡与超级岛卡片的展开/收起经 `:superislandui` 的 `SuperIslandExpandableCard` 做形态变换：外框单层绘制底色并在两态颜色与透明度之间渐变，宽高由同一进度插值到两态实测尺寸，圆角随进度增大到胶囊圆角，两态内容顶部锚定并以互补透明度交接。两个方向都按先快后慢缓动，展开时长长于收起。

扩展点统一为 `OverlayFeature` 抽象加注册表。`:overlay-api` 定义数据模型与能力接口，无实现、无内部依赖，只被 `:desktop` 消费。

<a id="overlay-settings"></a>

## 叠加层设置

设置采用「主页加五个子页」结构。数值项用 `SliderPreference`，公共辅助为 `OverlaySlider`。

拖动回调里不做步进吸附：拖动期用本地状态跟手，`onValueChangeFinished` 再吸附提交。

渲染侧不逐帧读 `Storage`。非锚点设置变更经 `DesktopOverlaySettings.revision` 与 `notifyChanged()` 通知，渲染侧只在版本号变化时重取快照；锚点位置经 Compose mutableState 实时跟手。
