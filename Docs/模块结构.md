# 模块结构

本文是 NotifyRelay Android 的当前模块结构契约：单例归属、仓储入口、状态机边界与端口注入要求。模块清单与依赖图见[文件用途基础说明](文件用途基础说明.md)，构建与验证口径见[开发约定](开发约定.md)。

<a id="app-list"></a>

## 应用列表

`feature/appslist/` 没有门面。`InstalledAppsRepository`、`AppIconRepository`、`PinnedAppsRepository`、`RemoteAppsCache` 四个 `internal object` 是唯一入口，调用方直连。

数据库一律取 `DatabaseRepository.getInstance(context)`。

<a id="device-and-notification"></a>

## 设备与通知

`feature/device/model/` 的 `NotificationRepository` 直接持有内存态（`notifications`、`currentDevice`、`deviceList`）与 `scanDeviceList`，中间没有 `NotificationMemoryStore` 层。

持久化入口是 `NotificationRecordStore.getInstance(context)`。

<a id="singletons"></a>

## 单例

进程级存储入口用伴生对象加双重检查锁：`DatabaseRepository.getInstance`、`NotificationRecordStore.getInstance`。

组合根是 `DeviceConnectionManagerSingleton`，向外暴露 `audioRelay`、`handshakeWaiters`、`stateQueryResponder`。

`ScrcpyUiViewModel.getInstance` 位于 `scrcpy` 子模块内，生命周期由子模块决定。

<a id="super-island-extras"></a>

## 超级岛 extras

`SuperIslandExtras` 只保留 extra key 常量与 `writePicMap`；`writePicMap` 承担前缀过滤与数量上限。调用方直接 `putXxx`，没有 `writeParam` 与 `writeStandardFlags` 包装。

<a id="apps-state-machine"></a>

## 应用列表状态机

`AppsStateMachine<T, K>` 的 `loader` 接收本次加载的键：本地取 `Unit`、远程取设备 UUID。键变化后不写回结果与错误，`CancellationException` 原样抛出。

`RemoteAppsViewModel` 持有 `loadJob`，新加载前取消上一次。同一时刻只有当前设备的列表能落到共享状态。

<a id="exception-handling"></a>

## 异常处理

异常捕获收窄到实际可恢复的具体类型，不用 `catch (e: Exception)` 包住整段业务。

通知与转发链路的下游已各自内部兜底：`AppListHelper`、`runReplicaCatching`、`SendGateway`、`ProtocolSender`、`NotificationPersistence.syncToCache`、`MediaMessageBuilder`。上游对它们的泛型捕获对 `Exception` 不可达。

持久化层只把 `SQLiteException` 视为可恢复失败。未预期缺陷记录后按边界暴露，不就地吞掉。

`CoroutineExceptionHandler` 放在 `launch(...)` 参数上在父 Job 处理异常时不生效，需放在更外层的 scope 上。

<a id="port-injection"></a>

## 端口注入

新增 `:shared` 的 `error("LocalXxx 未提供")` 端口后，必须同时在 `ProvideAndroidUiPorts` 与 `ProvideDesktop*` 中 provides。漏一处只在运行时暴露，编译期无感。
