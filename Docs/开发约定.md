# 开发约定

本文是 NotifyRelay Android 的当前状态事实：UI 与交互约定、模块 API 版本边界、代码检索入口与 Git 工作流。常驻命令见[根指令](../AGENTS.md)，文档层级与写作规则见[文档标准](AGENTS.md)。

<a id="ui-and-interaction"></a>

## UI 与交互约定

Compose 组件优先使用 Miuix 主题库（`MiuixTheme`、`MiuixIcons`、`Button`、`Card` 等）；查阅 Miuix 用法一律走 `miuix-mcp`，不抓取官方文档网页。导航使用 Miuix Navigation3 + NavigationEvent。

页面根容器默认背景统一使用 `MiuixTheme.colorScheme.background`：内容区一律用 `background`，TopAppBar 可保留默认 `surface` 形成色差。独立页面（含子页、开发者模式）优先复用公共组件 `ScrollableTopAppBarPage`。

<a id="api-levels"></a>

## 模块 API 版本边界

`:app` minSdk = 31（Android 12），其余库模块（`:base`、`:data`、`:superislandui`、`:nativecore` 等）minSdk = 29（Android 10）；`:scrcpy` minSdk = 26（子模块自带配置）。不要为低于模块声明 minSdk 的版本编写兼容性代码。

模块命名：`:core` 指 Android 原生核心（Rust FFI），源码目录为 `nativecore/`，内含 `notify-relay-core` 子模块；该模块 Gradle 名与源码目录不同名，由 `settings.gradle.kts` 重定向。模块清单、依赖关系与各类职责见[文件用途基础说明](文件用途基础说明.md)。

<a id="code-search"></a>

## 代码检索

工作区已完成 CodeGraph 索引，位于 `E:\GitHubCode\01Main\NotifyRelay\.codegraph\`；`Android/` 自身无索引。代码定位、理解、调用关系与改动影响面一类问题第一步用 `codegraph_explore` MCP，`projectPath` 传工作区根。

<a id="git-workflow"></a>

## Git 工作流

功能开发在独立分支进行，合并到 `main` 推荐 `--no-ff` 以保留分支提交记录。`dev` 为开发主线，`main` 为发布来源。

钩子需每个克隆手动启用一次：`git config core.hooksPath .githooks`。Git 不允许钩子路径随仓库自动生效；换机器、重新克隆或新增协作者后必须重新执行。`pre-commit` 只跑 `ktlintFormat`；`pre-push` 先跑 `pnpm run verify-all` 再跑 `ktlintFormat`，因为中间状态常带未修完的问题，压在提交上会挡住改动本身。
