# `:desktop` — 叠加层

无边框、透明、置顶、点击穿透且不抢焦点的窗口，尺寸随内容收缩并固定在屏幕顶部居中，用 Compose 直接绘制媒体卡、超级岛卡片、电池汇总岛、通知卡片与状态元素。叠加层契约见[桌面端](../../桌面端.md#overlay)，扩展点抽象见[模块结构](../../模块结构.md)。

## 布局

窗口内容只有一列，宽度固定为 `OVERLAY_COLUMN_WIDTH`（420dp），距屏幕顶部 10dp。列内自上而下为媒体卡、超级岛、通知卡片、状态行；整列尺寸经 `onSizeChanged` 交给 `DesktopWindowsOverlay.moveTo`，窗口随之改成「屏幕水平居中 + 内容尺寸」。

列由 `OverlayColumn` 按「独立行 + 填空隙」排布；条目以唯一键登记，内容不发出节点时（关闭的元素、空的文案）按零尺寸跳过，不占行也不占位：媒体卡、超级岛卡片、通知卡片与电池汇总岛各占一条独立行并水平居中；时间、键盘、余额与收起态通知图标按顺序尝试填进这些独立行左右剩下的空档，两侧分别贴向居中元素，不贴列边。填不下的条目留到后续行，全部行处理完后仍未安置的按自身宽度折行居中排在末尾；空档是否够用按实测宽度判定。

## 渲染

### `DesktopOverlayWindow.kt`

窗口与内容装配：创建透明无边框窗口，应用叠加层样式与点击穿透，启动置顶监控，并驱动帧时钟（频谱与映射提示淡出）与超级岛超时回收。可交互区域集合在此持有，经 `snapshotFlow` 提交给原生层；`DebugFlags.OVERLAY_REGION_DEBUG` 开启时叠加 `RegionDebugOverlay`。前台全屏检测开启且命中时整列内容不组合，窗口保持原尺寸。

### `NotificationCards.kt`

通知卡片层：卡片与图标方块两种形态。最多 2 张卡片同时展开，其余按到达顺序排队等前面的收起；每张展开 3 秒后收起为 24dp 图标方块，图标自收起时刻起存活 12 秒后移除。展开态为黑底圆角卡，左侧应用图标，右侧依次为「应用名 · 设备名」、标题与正文（正文最多两行）。展开态卡片独占一行并居中，收起态图标方块并入状态行。展开与收起状态由 `NotificationCardsState` 统一持有，两处渲染读到同一份状态。图标方块是唯一可点击的通知元素，点击重新展开并登记可交互区域。

### `DesktopSuperIslandCard.kt`

超级岛卡片：按 `paramV2` 选择渲染方式（媒体大岛 / 摘要区 A-B / 模板组件），3 秒后收起为摘要胶囊，超时无更新被移除。仅摘要类业务（手电筒）不展开。计时器按内容接收时刻换算到本地时钟，远端内容的时钟偏差不进入显示值。

全部时长与过期判据来自 `:domain` 的 `ReplicaTiming` 与 `ReplicaExpiry`，与 Android 端共用同一份实现，本模块不另立数值。「无更新」按内容判定而非按报文到达：对端会周期性重发同一份报文，`putSuperIsland` 在标题、正文、`paramV2` 与图片都未变时沿用原有的 `updatedAt`，因此重发不会推迟超时回收。回收循环按最近一条的剩余存活精确休眠，不用固定周期，否则实际存活最长会翻倍。`addNotification` 同理按 id 替换而非追加。

### `MediaIslandCompose`（`:superislandui`）

媒体大岛：有进度信息时在正文与操作按钮之间显示细进度条与两端时间，中间按钮随播放态显示「播放」或「暂停」。进度按本地时钟推进，暂停即停。`SuperIslandExpandableCard` 的 `collapsedProgress` 给出时，收起态把白色描边换成沿胶囊轮廓的绿色进度环，按进度比例从左侧圆弧下端起顺时针填充；进度环画在裁切层之外，线宽不被裁掉。卡片外框尺寸取两态内容的实测尺寸，不随父约束撑满。

### `BatteryIslandCard.kt`

电池汇总岛：所有设备合并为一条与超级岛同形的卡片。两态都以设备名与电量图标为外显内容，收起态不显示具体电量值，设备名超出宽度时滚动显示；展开态逐台补上电量值与充电状态（离线、充电中、慢充、已充满、充电异常）。电量、充电状态或在线状态变化时自动展开 3 秒；交互开启时点击胶囊手动展开、点击展开态收起，胶囊登记为可交互区域。无可用设备时不绘制。设备集合由电池开关与隐藏离线开关决定。

### `OverlayElements.kt`

状态元素渲染：时间、键盘、余额；文本为黑色描边层与彩色填充层叠放，无背景卡片。键盘元素为按键盒（蓝底白边圆角，每行最多 10 个，映射提示黑底显示在按键行下方并在最后 30% 时长淡出）：按下键全部映射为键名显示，Caps Lock 开启显示「大写」，Num Lock 常态开启、仅关闭时显示「NumLk关」，Scroll Lock 开启时显示。时间元素只读 `DesktopOverlayStore.clockText`，不自行计时。

### `OverlaySpectrum.kt`

频谱条动画：五条双波峰震荡的合成波形，随帧时钟推进。暂停时各条收起到 8% 的残留高度并齐平，恢复播放再涨回震荡高度，两个方向都按 220ms 缓动。

### `DesktopWindowsOverlay.kt`

Win32 原生能力：窗口样式、置顶强化（peer 变化检测、最小化恢复、调用后验证）、点击穿透切换、前台全屏检测、`moveTo` 几何提交。以窗口坐标判定鼠标是否位于可交互区域内，仅在状态变化时把 `SetWindowLong` 投递到 EDT；原生操作失败后降级并停止重试。

### `DesktopSuperIslandInbound.kt`

超级岛入站处理：报文由 Rust core 归一后写入 `DesktopOverlayStore.superIslands`。

## 矢量场景管道

`OverlaySceneBridge` 把叠加层内容录成位图帧，经 `NamedPipeSceneServer` 推给 Gamebar 小组件；无客户端订阅时不录制。管道以 `FILE_FLAG_OVERLAPPED` 创建，读写走重叠 I/O 并各自建完成事件：单次写上限 3 秒，超时即判对端停止读取并重建实例；关闭先 `CancelIoEx` 再 `CloseHandle`，等待监听线程退出交给独立线程。二者都不可省——同步写在对端不读时会永久停在内核里，而 `CloseHandle` 又会等这条请求结束，互锁会连界面线程一起卡死；`OverlaySceneBridge.close` 同样转交独立线程。

## 扩展点

### `DesktopOverlayFeatures.kt`

扩展点装配：持有四项 `OverlayFeature` 实现并统一启停；具体生命周期与数据订阅由各 Feature 自管，本类只做编排与供设置页访问的委托。`current` 供设置页即时同步

### `DesktopBalanceFeature.kt`

余额扩展点：实现 `OverlayFeature`，封装 `DesktopBalanceSource` 的生命周期与数据订阅，注册到 `OverlayFeatureRegistry`

### `DesktopBatteryFeature.kt`

电池扩展点：实现 `OverlayFeature`，封装 `DesktopBatterySource`

### `DesktopKeyboardFeature.kt`

键盘扩展点：实现 `OverlayFeature`，封装 `DesktopKeyboardSource`

### `DesktopClockFeature.kt`

时间扩展点：实现 `OverlayFeature`，封装 `DesktopClockSource`（纯 JVM）

### `DesktopClockSource.kt`

时间数据源（纯 JVM，无 JNA）：`java.time.LocalTime` 按配置格式化，秒级或分钟级刷新

### `DesktopBalanceSource.kt`

DeepSeek 余额数据源：JDK `HttpClient` 轮询 `/user/balance`，优先取 CNY 余额；余额未变只刷新末条时间，变化时追加并算变化量；历史超 500 条时合并最旧的同向连续项

### `DesktopBalanceHistoryStore.kt`

余额历史持久化（JSON 落 `Storage`）

### `DesktopBatterySource.kt`

电池数据源：后台协程按 30 秒轮询枚举（阻塞 HID IO），结果与上次一致时不广播

### `BatteryNative.kt`

经 UniFFI 生成的 `notifyrelay.battery.ffi.BatteryLib` 绑定枚举设备：`enumerateDevices()` 返回 `BatterySnapshot`，转换到 `BatteryDevice` 时把无电量或离线的电量记 -1。绑定由 `:desktop:uniffiBatteryBindgen` 依子模块 `uniffi.toml` 生成到 `desktop/build/generated/uniffi-battery`，分别注册进 commonMain（`expect` 声明）与 jvmMain（`actual` 实现）；`kotlin_targets` 只列 `jvm`，且 jvm 目标须开 `-Xexpect-actual-classes`，`kotlin_multiplatform = false` 只产出接口而无实现类。

### `DesktopKeyboardSource.kt`

键盘监控数据源：自建专用线程安装全局低级键盘钩子并泵消息循环（`WH_KEYBOARD_LL` 回调只投递到安装线程）；回调内只更新状态并合并推送，切换键在按下时翻转锁定状态（初值在安装时经 `GetKeyState` 读取）；修饰键以 `GetAsyncKeyState` 全局真值为准并每 50ms 轮询自愈（钩子漏掉抬起边沿时下次轮询清除）；推送按快照等值跳过，映射命中时投递提示

### `KeyboardHookBridge.kt`

钩子原生封装：`SetWindowsHookExW` / `UnhookWindowsHookEx` / `GetMessageW` 消息泵 / `PostThreadMessageW` 退出 / `GetKeyState` 读取 / `GetAsyncKeyState` 全局按下状态

## 开关口径

扩展点与显示层复用同一窗口，不引入宿主编排器：`DesktopOverlayFeatures` 在窗口创建后装配。开关口径为「叠加层总开关 + 各元素开关」同时满足才生效，总开关关闭时不创建窗口也不启动扩展点；键盘项的全局低级键盘钩子随该口径安装与卸载，不做常驻。默认值：余额默认关（填入凭据后由用户开启），电池、键盘、时间默认开。余额与电池的枚举/轮询在后台，键盘钩子在专用消息泵线程，均不占用渲染线程。非外观设置（交互、频谱、操作按钮、收起时长）经 `revision` 观察，切换即时生效。
