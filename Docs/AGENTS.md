# AGENTS.md — 文档标准

本文定义文档结构、Markdown 层级、写作规则与 `verify-doc-budgets` 的预算上限。必需覆盖范围与编辑判断用 [notifyrelay-prose-standard](../.agents/skills/notifyrelay-prose-standard/SKILL.md)。

<a id="document-structure"></a>

## 文档结构

这些规则适用于人读的文档；[Agent Notes](../.agents/notes/README.md) 不在其范围内。一篇事故复盘是以事故为界的参考页；其时间顺序记录证据，不是教学顺序。主题与树中位置定其范围：详述自身主题，直接子项只写用途、职责与高层行为，更低层细节链接到拥有它的后代；文档类型不放宽该范围，参考页只可穷尽自身主题。测试机制、fixture 与 harness 放在最低拥有层，更高层链接过去。

每篇范围内文档归为教程或参考页。教程沿通往某结果的有序路径展开，只引入每步所需内容。参考页定义查询范围与当前行为，无教学顺序。两者内容可观时分开；任一部分较小时给该节加标注。

写教程前，先私下判定读者起点与各概念层级：入门、进阶或高级。先讲前置概念再讲依赖它的，难度逐级上升，非必要的高级材料移到后续教程或参考页。

写作顺序：在树中定位文档；定其允许的细节层级；选定教程或参考页；教程则按前置关系与难度排列概念；搬走属于后代的细节；用指向拥有者的链接取代下层解释。

<a id="the-tier-taxonomy-one-home-per-fact"></a>

## 层级分类：一个事实一个家

每个事实只有一个家：职责所在的那个层级；别处只准链接。

| 层级 | 职责 | 不属于这里 |
|---|---|---|
| 根 `AGENTS.md` | 常驻指令：agent 每个会话都要在上下文里的规则，每条一到三行，并链接其正家 | 故事、完整示例、场景化流程、任何从被链接正家复述来的内容 |
| 子树 `AGENTS.md`（`Docs/`、`.agents/notes/`） | 该子树专属的指令 | 根文件已承载的全仓规则 |
| [Agent Notes](../.agents/notes/README.md) | 活跃决策记录：为什么、放弃了什么、必需验证；`implemented/` 记录以现在时描述已交付的现实 | 迁移计划、验收任务清单、fixture 走查，以及决策已交付后的规格腔（「应当…」）；归档记录是冻结的历史，永非当前权威 |
| 缺陷类别规则页 | 本仓库在评审中执行的规则，按制品拆分：一页通用缺陷类别，加逐领域页 | 类型定义与语义、决策理由（→ Agent Notes） |
| 事故复盘页 | 事故故事——唯一承载亲历叙事的层级 | — |
| 测试策略页 | 测试层级、证据选择、执行拓扑与资源归属 | 会与脚本漂移的逐项检查清单；设计理由（→ Agent Notes） |
| 技能（`.agents/skills/`） | 可复用工作流与专门判断标准 | 产品与运行时契约（→ docs 或源码） |

上表中缺陷类别规则、事故复盘与测试策略三层各有其页：[缺陷类别规则](缺陷类别规则.md)按制品收拢评审强制项，[测试策略](测试策略.md)记录层级与证据选择，[事故复盘](事故复盘.md)承载亲历叙事。新增常驻文档时在同一次改动里补上预算上限。

放置：bug → 事故复盘；理由 → Agent Notes；流程 → 技能或教程；类型定义 → 参考页；契约 → README；常驻指令 → 根 `AGENTS.md` 并附理由链接；评审强制规则 → 缺陷类别规则页。

<a id="writing-rules"></a>

## 写作规则

- **文档写当前状态。** 历史留在提交、pull request、Agent Note 与事故复盘中。其他散文只点现有机制，不写变更或栈位置。
- **适用 Agent Note 创建标准。** 机械或局部改动豁免，包括局部 UI 改动；保持既有归属记录准确（[范围](../.agents/notes/README.md#何时需要写一份)）。
- **每段一个物理行**（`verify-md-wrap`）：用编辑器软换行。代码块、表格与列表结构保持原格式；代码注释不超 linter 的列宽上限。
- **注释与 JSDoc 写完整契约，不写思考记录。** 保留行为、失败、时序、归属、情态、例外、后果与非显然的指向；删除过程叙述、测试走查、评审分析与代码复述。保留局部契约并链接其理由。细节见 [notifyrelay-prose-standard](../.agents/skills/notifyrelay-prose-standard/SKILL.md)。
- 直接陈述：点明主体与事实（[参考](../.agents/skills/notifyrelay-prose-standard/SKILL.md)）。`seam` 只用于已定义的能力。写准确的门禁、类型、API、操作或行为名，不用隐喻性的「gate」「vocabulary」「surface」。

<a id="wordcount-budgets"></a>

## 词数预算

[doc-budgets.manifest.json](../scripts/doc-budgets.manifest.json) 设定常驻文档上限；`pnpm run verify-doc-budgets` 拒绝超限或缺失文件。`doc-system.config.ts` 的 `budgetCoveragePatterns` 声明哪些文档必须逐篇有上限，漏配同样失败，因此新增常驻文档时在同一次改动里补上条目。计数把每个 CJK 字符算一个词，因为只按空白切分会把中文页读成几十个词。

门禁变红时：

1. **搬迁**属于其他层级的内容；需要时留一行链接。
2. **压缩**留在此处但可以更短的表述。
3. 只有内容确实需要空间时才**上调**上限；在改动中说明清单 diff 的理由。上限过低是预算缺陷。

上限是护栏，不是压缩目标。处于或低于目标时保留至少 5% 余量；高于目标时冻结上限，直到搬迁或压缩把文档带回目标以下。文档仍有空间时才下调上限。

<a id="the-slop-checklist"></a>

## 赘余清单

在任何文档里搜这几类：

- 重复的规则：搜有辨识度的短语；只留一个家，其余改成链接。
- 越层的历程：陈述当前事实，并链接历史正家。
- 散文或图中的实现状态标注（「已实现！」「未来：…」）。状态会腐烂；树布局承载它。
- 源码或生成器已是权威时，手工复述的目录、JSDoc，或测试与状态清单。
- 思考记录：逐步实现叙述、显而易见分支的证明、测试走查，或被否决的局部方案。保留最终契约或可长期沿用的理由；删除推导路径。
- 理由散在同类方法旁反复出现，而非在拥有的能力或 helper 处写一次。
- 段落墙：一段承载多条规则与括号插注。拆开，或把细节下放到它的家。
- 强调通胀：到处加粗、大写或「关键的是」等于什么都不突出。只强调改变行为的那个分句。
- `implemented/` Agent Note 里的规格腔：「should」（应当）、迁移计划、验收清单。已实现的 Agent Note 按[已实现记录说明](../.agents/notes/implemented/AGENTS.md)描述现状。
