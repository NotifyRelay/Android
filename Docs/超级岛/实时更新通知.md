# 实时更新通知

实时更新（Promoted Ongoing）让进行中的活动以更醒目的方式出现在通知抽屉顶部、锁屏与状态栏。本文定义发布资格、系统提供的查询接口与状态条状标签的行为；澎湃os的岛通知与焦点通知的模板见[模板库](模板库.md)，接入总览见[超级岛](../超级岛.md)。

<a id="eligibility"></a>

## 发布资格

系统会推广实时动态通知。被推广的通知卡片默认处于展开状态，不可折叠。

通知必须满足以下全部要求，才会成为实时更新：

- 必须为标准样式、BigTextStyle、CallStyle 或 ProgressStyle。
- 必须在 Android 清单中请求 `android.permission.POST_PROMOTED_NOTIFICATIONS`（非运行时权限）。
- 必须使用 `EXTRA_REQUEST_PROMOTED_ONGOING` 或 `NotificationCompat.Builder#setRequestPromotedOngoing` 请求提升。
- 必须为 ongoing，即设置 `FLAG_ONGOING_EVENT`。
- 必须设置 `contentTitle`。
- 不得设置任何 `customContentView`（无 RemoteViews）。
- 不得是使用 `setGroupSummary` 的群组摘要。
- 不得将 `setColorized` 设置为 TRUE。
- 通知渠道不得具有 `IMPORTANCE_MIN`。

原始设备制造商（OEM）可以强制执行关于实时更新资格的其他条件。

<a id="promotion-api"></a>

## 提升状态查询

以下 API 用于判断系统是否会提升某条通知：

| API | 作用 |
|---|---|
| `Notification.FLAG_PROMOTED_ONGOING` | 表示通知是否为推广通知 |
| `Notification.hasPromotableCharacteristics()` | 验证系统是否可以升级通知；不考虑用户是否在设置中为应用停用了实时更新 |
| `NotificationManager.canPostPromotedNotifications()` | 检查应用是否可以发布推广通知，例如用户是否在设置中启用或停用了该能力 |
| `Settings.ACTION_MANAGE_APP_PROMOTED_NOTIFICATIONS` | intent 操作，把用户送到「设置」以启用该能力 |

<a id="usage-conditions"></a>

## 使用条件

实时更新适用于正在进行、由用户发起且对时间敏感的活动。

<a id="ongoing"></a>

### 正在进行

实时更新必须表示正在积极进行的活动，并且具有明确的开始和结束时间。活动发生在过去时用标准通知；尚未开始的活动同样如此，不过即将开始的活动可以使用实时更新。

实时动态表示正在进行的活动。不要用实时更新提供对应用功能的加速访问——那类需求使用应用 widget 或自定义「快捷设置」功能块。

适用场景：正在进行的导航、正在进行的通话、正在进行的网约车跟踪和正在进行的外卖跟踪。

不当用途：广告、宣传内容、聊天消息、提醒、即将到来的日历活动，以及应用功能的快捷访问方式。

<a id="user-initiated"></a>

### 用户自行触发

大多数实时更新应表示由用户明确触发的活动，例如开始锻炼、启动驾车导航或叫网约车。不要在实时更新中显示环境信息，例如用户环境、兴趣或即将进行的活动的相关信息。不允许由其他方触发的活动生成实时更新。

用户可能在将来某个时间才参与某活动，例如购买机票或音乐会门票、报名参赛。这类场景可以在预定活动开始时自动显示实时更新，但触发器必须调整到活动即将开始时才显示。用户明确表示要监控某个后台事件（例如体育赛事）时，可以开始针对该事件发布实时更新，同时在关联通知中添加取消固定操作。

<a id="time-sensitive"></a>

### 具有时效性

仅当实时动态需要在整个活动期间引起用户注意时才显示。实时更新的主要使用场景是监控：用户通过快速查看实时更新密切关注活动进展。

对于在实时更新和常规通知之间转换的 activity，实时更新通常合适。例如在用户航班起飞前数小时显示登机牌通知是合适的，但只有在用户到达机场或活动场地、或登机开始时，该通知才应变为实时更新。实时更新不适合跟踪软件包，因为用户无需持续监控。

<a id="status-chip"></a>

## 状态条状标签

借助状态提示，用户可以在通知未显示时跟踪实时更新。使用 `setShortCriticalText` 或 `setWhen` 传达与进度中心通知相关的重要状态信息。

| 形态 | 用法 |
|---|---|
| 带有图标的状态条状标签 | 不确定状态会显示小图标，由 `Notification.Builder#setSmallIcon` 设置 |
| 带有时间的状态条状标签 | `Notification.Builder#setShortCriticalText` 显示绝对时间 |
| 带有信息的状态条状标签 | `Notification.Builder#setShortCriticalText` 传达重要信息 |

<a id="time"></a>

### 时间

时间会触发通知时长的倒计时，除非通知被关闭或更新。

- 「何时」时间至少比当前时间晚 2 分钟：如果当前时间为上午 10:05，而「何时」时间设置为上午 10:10，则芯片显示 5 分钟。
- 「何时」时间为过去时间：不显示文本。
- 使用计时器时，芯片中的计时器可以显示时间，见 `setUsesChronometer` 与 `setChronometerCountdown`。只要计时器时间为正数，就会在功能块中显示。
- 不希望显示时间：用 `setShowWhen` 设置为 FALSE。

<a id="chip-appearance"></a>

### 外观

状态条状标签始终包含一个图标，可以选择性地包含文本。微芯片的最大宽度为 96dp，只有当整个文本都能放入 chip 中时才显示文本：

- 少于 7 个字符时显示整个文本。
- 只有不到一半的文字会显示时，仅显示图标。
- 超过一半的文字会显示时，尽可能显示更多文字。

<a id="dismissal"></a>

## 关闭

用户可以在通知栏中控制通知的显示情况。发布不必要的实时更新可能导致用户撤消应用的发布权限。

为避免用户完全停用实时更新，不要发布用户可能会关闭的更新，也不要重新发布用户已关闭的实时更新。使用 `setDeleteIntent` 检测已关闭的更新。
