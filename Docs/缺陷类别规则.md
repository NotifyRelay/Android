# 缺陷类别规则页

本文是本仓库在评审中执行的规则，按制品拆分：通用类别、状态与归属、Kotlin 与 Compose、KMP 与绑定、文档与门禁、错误处理。类型定义与语义见[模块结构](模块结构.md)与各模块页，决策理由见 [Agent Note](../.agents/notes/README.md)。评审与实现时对照本页；能变红的规则同时给出所属门禁。

<a id="general"></a>

## 通用类别

- **死代码与投机性参数。** 未被生产调用方使用的公开能力、只有测试使用的分支、为将来预留的配置项都是候选删除项。判断标准与调研方法见 [notifyrelay-find-simplifications](../.agents/skills/notifyrelay-find-simplifications/SKILL.md)。
- **重复定义。** 同一事实在代码、文档、配置中重复出现时留一个家，其余改成引用。散文层的判据见[文档标准](AGENTS.md#the-slop-checklist)。
- **共享状态无归属。** 模块级可变状态、缓存、注册表必须挂到服务、实例或显式作用域上；进程级单例的现有归属见[模块结构](模块结构.md#singletons)。
- **吞掉失败。** 空 `catch`、只打日志的捕获、把异常转成成功返回都是缺陷；失败需要类型、处理归属、遏制方式与失败后仍然成立的保证，见[错误处理](#error-handling)。

<a id="state-and-ownership"></a>

## 状态与归属

- **捕获范围宽于恢复能力。** 捕获限制的是异常传播范围，不是变更。只有受影响状态的所有者才能确立安全继续；否则停止依赖工作、丢弃无效状态或实例，或升级上报。
- **键变化后写回结果。** 带键的异步加载在新键生效后不得写回旧结果与错误；`CancellationException` 原样抛出，不转成错误态。
- **端口漏注册。** `:shared` 声明新端口后必须在 Android 与桌面组合根同时 provides；漏一处只在运行时暴露。当前组合根见[模块结构](模块结构.md#port-injection)。

<a id="kotlin-and-compose"></a>

## Kotlin 与 Compose

- **低于模块 minSdk 的兼容分支。** 模块已声明 minSdk 时，不为更低版本写兼容代码；边界值见[开发约定](开发约定.md#api-levels)。
- **绕过公共组件重建页面骨架。** 独立页面优先复用 `ScrollableTopAppBarPage`，主题与背景取 `MiuixTheme.colorScheme`，不手写等价容器。
- **非必要警告抑制。** 先处理实际可处理的警告；只有警告所指向的逻辑本身必须如此时才保留，且要写明理由。当前基线见[构建与验证](构建与验证.md#warning-baseline)。

<a id="kmp-and-bindings"></a>

## KMP 与绑定

- **源集放错。** 平台无关代码进 `commonMain`，平台差异进 `androidMain`/`jvmMain`；跨源集的依赖方向与注册方式见 [KMP 与绑定](KMP与绑定.md)。
- **手改绑定生成物。** `nativecore/build/generated/uniffi-kmp/` 由构建生成，改动必须落在 Rust 侧定义或绑定声明。
- **模块名与目录名不一致被当成缺陷。** `:core` 的源码目录是 `nativecore/`，由 `settings.gradle.kts` 重定向；这是既定契约，不是错误。

<a id="docs-and-gates"></a>

## 文档与门禁

- **文档记录变更历史。** 变更历史属于 Git 提交、Agent Note 与事故复盘；其他散文只描述现有机制。判据见[文档标准](AGENTS.md#writing-rules)。
- **硬折行段落。** 每段一个物理行；`pnpm run verify-md-wrap` 拒绝跨行段落。
- **没有门禁的新规则。** 新增一条被评审强制的规则时，同一次改动给出能让它变红的门禁，并按[根指令](../AGENTS.md#校验)的校验表取证。
- **新增常驻文档漏配预算。** `Docs/`、`README.md`、`AGENTS.md` 与 Agent Note 规则页都在 `budgetCoveragePatterns` 覆盖范围内；漏配会让 `pnpm run verify-doc-budgets` 变红。

<a id="error-handling"></a>

## 错误处理

- **未经定义的失败类型。** 预期内的失败要有声明的类型、稳定判别值与处理相关细节；机器身份与展示文本分开，不解析消息文本来路由处理。
- **只打日志的上报。** 最终报告需要可读摘要、受影响操作与安全下一步；不受信任的状态必须经 UI 或默认开启的日志可见。
- **宣称未验证的恢复。** 没有保证时不得宣称成功、回滚或可安全重试；验证对象是结果状态与可见结果，不只是异常被捕获。

完整原则见 [notifyrelay-error-handling](../.agents/skills/notifyrelay-error-handling/SKILL.md)。
