# 2026-11-03 桌面端剪贴板回灌与转义损坏

<a id="impact"></a>

## 影响

桌面端（`:desktop`）把远端剪贴板内容写回本机剪贴板时，含路径或换行的文本被改写：反斜杠每经一次回灌多一层（一个变两个、两个变四个），换行符变成字面反斜杠加 `n`，含引号的内容在第一个引号处被截断。粘贴出的内容与复制时不一致——路径失效、多行变单行、引号之后的内容丢失；剪贴板只保存最后一次写入的值，无持久数据损失，受影响的是同步过去的内容本身。图片另有独立缺口：剪贴板中的图片是平台重编码后的 PNG，与线上 Base64 不同，回灌每次都会被当成新的本机复制再发一次，直到频率限制把回环掐断。

<a id="causal-chain"></a>

## 因果链

1. 触发与回灌。`onReceived` 把远端内容写回系统剪贴板，`ClipboardChangeMonitor` 又把这次写入当成本机变更回调 `handleClipboardChange`，同一份内容被再次送入发送流程。
2. 平台判定不可靠。平台自持的 `lastSignature` 在写入之后才赋值，而写线程（Rust 分发线程）与判定线程（窗口消息线程）不同；异步投递的 `WM_CLIPBOARDUPDATE` 存在事件先于赋值被处理的窗口。图片分支更是必然失配：登记的是入站 Base64，回读值经重新编码。
3. Rust 闸门失效。`clipboardOnChanged` 的防循环与"内容未改变"都以内容字符串相等为前提，而平台交给它的内容已被改写，两道闸门全部落空。
4. 改写来源。`parseField` 用 `indexOf('"')` 裸切 Rust 的 `serde_json` 输出，不做反转义：`C:\a` 变成 `C:\\a`，换行变成字面反斜杠加 `n`，引号处截断。
5. 图片缺口独立于解码。剪贴板不接受 Base64 文本作为图片，平台必须解码成图像写回，回读又只能重新编码，因此线上形态与回读形态永远不同，内容相等这条判据对图片不成立。
6. 放大。改写非幂等，每经一次回灌多叠一层转义，与第 1 条叠加即表现出的"路径分隔符累积"。

失效的保证：平台侧判定（第 2 条）、Rust 内容相等前提（第 3 条）、平台侧 JSON 解码正确性（第 4 条）、Rust 对图片回灌的覆盖（第 5 条）。

<a id="containment-and-recovery"></a>

## 遏制与恢复

判定回到 Rust core 独占：平台删掉自持的内容哈希，只做系统剪贴板读写与口径归一；Rust 的 `normalize_content` 在收发两侧统一换行，使平台回读值与接收登记值逐字相等，防循环改为按归一化内容比较而不要求类型一致（安卓把接收到的图片以 data URL 文本写回剪贴板，经 Fcitx5 广播回来时类型已是 text，限定类型会漏判），图片另按类型与时间窗兜底。平台回包改为按 JSON 语法解码，解码失败放弃写入并记警告。安卓端写回形态同批收口：收到的图片从 data URL 文本改为内容 URI，否则 Fcitx5 会把它记成剪贴板条目并按文本广播回对端，用户粘贴也只会得到 Base64 串。恢复后仍然成立的保证：去重、防循环、频率限制与 2MB 阈值全部由 Rust core 闭环；剪贴板与远端同口径仍为 `LF`；平台侧不再有任何同步状态。

<a id="send-path"></a>

## 追加：桌面端从未发出过剪贴板

修复回灌后用真机复现，桌面端复制任何内容都不出现在安卓剪贴板，桌面日志每次都停在 `Rust 判定：action=skipped reason=no targets`。原因是拼装目标 uuid 数组的那行写成 `targets.joinToString(prefix = "[", postfix = "]") { """ + it.uuid + """ }`：三引号把字面量 ` + it.uuid + ` 当成了字符串内容，产出非法 JSON；Rust 侧用 `serde_json::from_str(...).unwrap_or_default()` 接住解析失败，静默退化成空目标列表，发送从未发生且不留痕迹。

这与回声是两条独立缺陷，但同一个教训：平台拼的报文必须由序列化库生成，解析失败也不能和"没有目标"共用一条静默路径。

<a id="prevention"></a>

## 预防

- Rust 单测锁定防循环：新增换行归一、CRLF 接收后的回灌判定、图片窗口内判定与窗口外放行。可执行门禁：`cargo test --lib clipboard`。
- 桌面端单测锁定平台义务：回包解码的 20 轮回灌恒等，以及换行归一幂等。可执行门禁：`./gradlew :desktop:jvmTest`。
- 平台侧不新增判定入口：回灌、重复与限频只有 `clipboardOnChanged` 一条路径，新增平台状态会立刻表现为第二处判定。
- 目标列表改由序列化库生成（`buildTargetsJson`），Rust 侧把"目标列表解析失败"与"没有目标"分开报告。回归用例 `ClipboardTargetsJsonTest` 与 `test_on_changed_for_reports_malformed_targets` 在旧实现下均为红。
