# Agent Note: 桌面端叠加层改为进程内窗口

Status: implemented

## Problem

桌面端叠加层原先是独立的 C# WinUI 子模块，经伴生进程与位图传输把画面送到主进程。这条链路要维护两套渲染实现、一次跨进程同步和位图编码，任何一环出问题都表现为画面不更新。JVM 端已经把主界面迁到 Compose，叠加层成为唯一还留在另一套技术栈里的部分。

## Decision

叠加层改为进程内无边框透明窗口，用 Compose 直接绘制；扩展点统一为 `OverlayFeature` 抽象加注册表。窗口、托盘、打包与叠加层的当前契约见[桌面端](../../../../Docs/桌面端.md)。

窗口几何与内容形态由[桌面端叠加层改为顶部固定列](2026-11-04-desktop-overlay-fixed-column.md)定义：本记录只保留进程内渲染与扩展点抽象这部分决策。

## Alternatives considered

**保留伴生进程加位图传输。** 这是原 C# 实现的形态。它让叠加层与主进程完全隔离，代价是两套渲染实现、一次跨进程同步与位图编码，且 JVM 侧已有 Compose 渲染能力可以复用。改用进程内窗口后省掉整条传输链路。

**用 AWT 原生托盘菜单。** 该 JDK 下中文显示为方块，不可用。Swing 菜单能显示中文但样式与 Miuix 不统一，且需要另做主题适配。

**用 `run` 代替 `runDistributable` 做日常运行。** `run` 每次都要构建且会掩盖打包产物的问题（例如缺失的运行时模块），`runDistributable` 才是接近安装后应用的形态。

## Consequences

打包产物的行为不能靠编译通过来验证，必须跑 `runDistributable`。叠加层的窗口样式与输入行为依赖 Win32 扩展样式，改动前要先确认点击穿透与焦点策略。
