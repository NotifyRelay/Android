# Agent Note: 异常捕获收窄到可恢复的具体类型

Status: implemented

## Problem

通知与转发链路曾用 `catch (e: Exception)` 包住整段业务。这类捕获对下游已经内部兜底的调用不可达，却会吞掉真正的缺陷：异常被记录成一次普通失败，调用方按可重试处理，实际是编码错误。

## Decision

异常捕获收窄到实际可恢复的具体类型，未预期缺陷记录后按边界暴露。下游兜底清单与协程处理器放置要求见[模块结构](../../../../Docs/模块结构.md#exception-handling)。

## Alternatives considered

**保留泛型捕获，只在日志里区分异常类型。** 日志区分不影响控制流：调用方仍按可恢复处理，缺陷仍被降级为一次失败记录。收窄捕获是唯一能让缺陷按缺陷暴露的方式。

**给每个下游调用点单独加捕获。** 下游已经内部兜底，再加一层只会重复处理同一失败，并把可恢复与不可恢复混在一起。

## Consequences

新增下游调用时先确认该下游是否已经内部兜底；已兜底的不要在外面再包一层泛型捕获。需要兜底的失败要写具体异常类型，并在注释里说明该类型为何可恢复。
