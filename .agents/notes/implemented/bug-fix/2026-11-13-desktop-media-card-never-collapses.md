# Agent Note: 桌面媒体卡的收起改由组合外的截止时刻驱动

Status: implemented

## Problem

提供位图给 Gamebar 的录制场景里，媒体卡一直停在展开态，从不自动收起。

原先的收起是组合内的延时协程：组件里 `LaunchedEffect(换曲键)` 先置展开，`delay(收起时长)` 后置收起。这条协程只在组合存活期间有效：场景重建、条目被重新加入组合、或换曲键抖动都会让协程重启，于是又回到`展开`。位图路径每帧重组由帧时钟驱动，问题不会自愈，表现就是永不收起。同目录的超级岛卡片用同一套写法，但它的内容键随每次更新变化、本来就该重新展开，因此没有暴露。

## Decision

展开态改为由「当前时刻是否早于截止时刻」派生，截止时刻记在组合之外的 `MediaCardExpansion`：按卡片（设备）持有，另记换曲键。

- 换曲键变了才重新计时；同一首歌内重复登记直接返回，不续期。这条同时挡住两类重建：每帧重组时 `LaunchedEffect` 会调用登记，组合整体重建时也会。
- 用户点开是唯一的重开路径，从点开时刻重新计时。
- 无记录或尚未登记本曲按展开处理：卡片刚出现应为展开态，登记发生在首次组合之后，按收起处理会闪一帧。
- 条目移除时丢弃该卡片的状态。

判断读「当前时刻」，因此到达截止时刻的那一帧就会切换，不依赖任何计时协程。

叠加层的时间基准同时改为由录制端提供：`OverlaySceneRecorder` 每录制一帧递增一个组合可见的帧脉冲，组合树读它并按墙钟算出 `frameNow`，不再用 `withFrameMillis` 自建帧时钟。位图路径下组合是否重组原本由组合内部时钟决定，时钟停摆时整列内容（收起、滚动、频谱、进度）会一起静止；改为录制端驱动后，只要录制循环在跑，时间就按帧推进。

## Alternatives considered

**保留延时协程，改用稳定键避免重启。** 键本来就稳定（换曲键、收起时长、设置版本），实际重启来自组合重建而非键抖动；键修不了重建。

**在录制器外面单独跑一个计时器去改状态。** 计时器与组合状态仍要同步，且状态一旦只存在组合里，重建后照样丢；把事实放到组合外才是根因修复。

**给媒体卡也加「内容变化就重新展开」。** 那正是歌词滚动逐句重开卡片的原因，与上一轮修掉的换曲误判相冲。

## Consequences

收起时刻不再随拖动设置里的「媒体卡自动收起」对当前这张卡即时生效：新的时长从下一次换曲或用户点开开始适用。这避免了改设置时把已收起的卡片重新拉起。

换曲键为空时（无歌曲身份且标题与歌手都为空）不登记，卡片按「无记录即展开」保持在展开态；这类会话本来也没有可靠的换曲依据。

卡片展开状态不再随条目重建归零，因此录制场景重建后看到的是同一状态，而不是每帧重新展开。

桥接器每两秒输出一次录制帧率与内容高度：帧率正常而画面静止说明问题在组合是否重组，帧率掉到个位数则说明帧没推出去，两者据此区分。
