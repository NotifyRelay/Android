# Agent Note: 安卓媒体胶囊的关闭残留与周期性重现

Status: implemented

## Problem

安卓端的胶囊展示有两个互相关联的现象，都出现在「媒体播放器的通知结束时连带关闭胶囊」这条正常路径上，用户手动移除展示的路径是正常的。

其一，媒体播放器的通知被移除、胶囊也已随之关闭之后，胶囊会在一轮刷新周期内重新出现。触发关闭的来源通知已经不在通知栏，重新出现的胶囊没有任何来源在驱动它。

其二，视频或不在标题/艺人字段推送歌词的媒体，胶囊会周期性消失一下再重新出现，重现时是展开态。

两个现象都出自展示与关闭两侧的时限没有对齐到同一个参照，而这个参照是通知监听服务的定时拉取周期。

- 展示侧：通知通道的兜底撤回是 30s，浮窗通道的媒体条目是 45s，两者口径本来就不一致。30s 与拉取周期相等，每轮拉取前都先撤回一次；来源仍在通知栏时，同一份内容被下一轮拉取重新展示，于是「消失一下再出现」。浮窗通道因为 45s 大于周期而没有暴露。
- 关闭侧：屏蔽窗口是 30s 固定值，同样等于拉取周期，窗口恰好在下一轮拉取时过期，已关闭的条目被重新拉起。
- 关闭侧的二次判定失效：`isSourceRecentlyClosedWithinMinute` 依赖「关闭时的版本」与「当前版本」相等，但关闭流程紧接着就删除了版本记录，当前版本恒为空，这个判定恒为 false。该守卫实际从未生效，留下的只有那条必然过期的 30s 窗口。
- 重新出现即展开来自系统行为：每份新通知按 `param_v2` 的 `islandFirstFloat` 默认 true 自动展开，所以只要发生重发，看到的都是展开态。

## Decision

展示与关闭两侧的时限统一以「来源刷新周期」为参照，常量集中在 `ReplicaTiming`：媒体展示的兜底撤回 45s、关闭屏蔽窗口为刷新周期加 15s、隐藏静默窗口 15s。

关闭屏蔽改为按**内容身份**判定，而不是单纯的过期时间。关闭时记下当时正在展示的内容标识（标题、正文与载荷），之后的展示请求只有在这份内容仍然相同的时候才被挡住；来源换了内容即视为重新开始，屏蔽解除。标识在展示越过全部守卫时由管线登记，读取与写入同源。

内容身份判定对三个展示通道一致生效：关闭标记在展示入口统一检查，不再出现「浮窗通道拦截、通知与列表通道在展示前清除标记」的差异。通道切换重建属于显式展示，仍先清除标记。

展示侧兜底撤回（`TIMEOUT`）不登记关闭标记：它表达的是「展示到时间了」，来源若仍在刷新就必须能重新展示。用户主动隐藏（`HIDDEN`）同样不登记，隐藏是可恢复的临时状态。

## Alternatives considered

**只把各处的 30s 拉长到 45s。** 能消掉周期性重现，但关闭残留仍在：来源在更长窗口的边界上照样会被拉回，只是间隔变长。

**保留版本号做二次判定。** 版本号在关闭流程里被删除，重新展示后从 1 重新开始，与关闭时记录的版本相等，关闭请求会被当成「对同一次展示的重复关闭」丢弃，胶囊反而关不掉。修复版本语义需要让版本跨关闭存活，代价与内容身份相当，而内容身份直接对应「这份内容结束了没有」这个真实语义。

**只在通知通道加「来源消失就不再展示」的门控。** 通知通道无从得知来源是否还活着，判断依据仍是通知栏里的活跃通知，而拉取周期内的中间态正是问题本身。

**媒体载荷显式写 `islandFirstFloat=false` 抑制重发时的展开。** 首次上岛也就不再自动展开，改变了正常表现；重发的根因是周期性消失，消掉消失即可。

## Consequences

媒体胶囊在来源持续活跃期间不再周期性消失，因此也不会因重发而反复展开。

来源通知结束后的关闭对**同一份内容**持续有效：来源在屏蔽窗口内重新投递同一份内容不会把胶囊拉回来，投递新内容则正常展示。窗口到期后内容身份不再被记住，此时的重发按新展示处理。

通知通道与浮窗通道的媒体撤回时限统一，两条通道的兜底行为不再因通道而异。

`ReplicaTtlRegistry` 不再持有版本快照，`isSourceRecentlyClosedWithinMinute` 与其依赖的 `closedSourceVersions` 一并移除；`SuperIslandSourceStore` 新增最近展示内容标识，随映射清理一同失效。
