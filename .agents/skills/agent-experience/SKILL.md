- **从最小上下文开始：** 先暴露目的、可用操作与约束，需要时再加载详细指令。
- **让发现路径显式：** 每个延后加载的资源都要有明确描述，以及可靠获取它的方式。
- **让关键约束可见：** 权限、破坏性影响与必需的校验应出现在相关操作之前。
- **优先有界输出：** 返回简洁结果，并附上可用于取回细节的标识符或路径；不要倾倒完整日志或文档。
- **利用就近性：** 在操作结果中附带有限量的、可能需要的相邻上下文，例如返回帖子回复时带上几条前置消息。显式标注省略与截断，并给出获取更多内容的方式。
- **评估总工作量：** 节省上下文只有在不引发更多搜索、重复读取或错误时才有价值。

<a id="tool-definitions"></a>

## 工具定义

- **删除显然的约束。** 省略模型能从调用结果中学到的规则，例如文件不存在导致读取失败，或发送失败未送达。
- **描述行为，而非实现。** 说明工具做什么、返回什么；省略内部机制、模型在结果中看到的输出标记，以及强制执行细节。
- **把参数规则放在参数上。** 默认值、取值范围、配对关系与何时设置的规则，属于该参数的描述或 schema；随配置变化的描述通常意味着变化的那部分应归属于某个参数。
- **每个事实只说一次。** 不要在系统提示词章节里重复工具定义，不要在工具描述里重复参数描述，也不要在一个工具里重复另一个工具的规则。
- **度量改动。** 比较工具定义改动前后的首轮提示词 token。
