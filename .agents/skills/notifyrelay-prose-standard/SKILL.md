# NotifyRelay 散文标准

写到足以保住契约为度，然后删除思考记录、重复与装饰。契约是调用方、被调方、实现方、生产者或消费方所依赖的义务、不变量、前置条件、后置条件或兼容性承诺。本技能负责编辑判断与必需的散文覆盖范围；放置位置与预算归[文档标准](../../../Docs/AGENTS.md)，追查并修复推理记录泄漏用 [notifyrelay-trim-cot-leakage](../notifyrelay-trim-cot-leakage/SKILL.md)。这是指引，不是脚本。

把 `contract`、`boundary`、`shape`、`surface`、`seam`、`gate`、`vocabulary` 当作使用前需要核对的词，而不是禁词。先问：确切的规则、API、字段集合、类型、校验、时序点、组件切分或失败，是否把该事实说得更准？当某个词命名的正是确切的技术对象时保留它，包括调用方/被调方契约与安全/进程边界。

注释描述代码无法表达的非显然契约或理由；它们不复述代码已经隐含的内容。

<a id="inputs-and-exclusions"></a>

## 输入与排除

要求显式给出 `scope`。缺失时报告所缺输入并停止；不要自行推断全仓范围，也不要开局访谈。

接受 `mode: automatic | interactive`，默认 `automatic`。只有当用户明确要求提问或校准时才进入交互模式。

`mode` 控制提问，不控制写权限。评审与审计任务只报告发现而不编辑；明确要求写入、修复或精简的任务才施加明确改动。

无论请求范围是否为全仓，发现、评审与编辑都要排除 `vendor/`。不要顺着符号链接进入该目录。把排除项放在包含 glob 之后，以免后续包含重新纳入它：例如 ripgrep 命令以 `--glob '!vendor/**'` 结尾，Git 命令给出显式的 `:(exclude)vendor/**` pathspec。若请求范围只含 `vendor/`，报告已无合格文件。

散文评审与编辑同时排除 `.agents/notes/archived/`。归档 Agent Note 是冻结快照；只有为了理解某条历史入站引用时才查看确切目标，绝不为了现代化其散文或出站链接。

把生成的目录、快照与 fixture 视为派生物。编辑前追踪每个消费方：源 JSDoc 也可能供给一份生成的面相模型的目录。先编辑拥有该内容的源或场景，再重新生成每个派生物。当生成器从拥有者散文中抽取摘要时，让被抽取的句子在该面上自足。遵循[轻量例行路径](../../../Docs/AGENTS.md#writing-rules)，只改需要改的那一面。

<a id="preserve-the-complete-proposition"></a>

## 保留完整命题

编辑前，识别段落中的每个命题。保留每一项相关事实：

- 主体与动作；
- 条件、时序与顺序；
- 情态，如必须、可以或绝不；
- 否定性保证与例外；
- 归属、副作用、失败模式与后果。

只有当每个事实分句都存活且结果更清晰时，才删除形容词、重复与叙述。单纯词数更少不是改进。

在使用点保留完整的局部契约：调用方或维护者在那里需要的行为、失败、归属与后果。架构、理由、算法、历史或长篇示例要果断链接到拥有它的文档。一个解释只有一个正家；必要的契约事实可以在本地重复。

若省略某条非显然理由可能导致误用或错误的简化，就保留它。否则陈述后果，并链接理由的正家。

<a id="required-coverage-by-prose-location"></a>

## 按散文位置要求的覆盖

这不是单向的缩短。当代码、类型与结构没有传达下列必需契约时，要补充或恢复散文。当这些事实在本地已显然可见时，不要加注释。

- **公开 JSDoc：** 记录调用方可见的返回值区分、抛出或拒绝、副作用、归属、时序、取消与持久性。
- **内部注释：** 为跨局部结构与明显复杂的局部结构提供指向，包括不变量、竞态顺序、归属、安全边界与意外的失败行为。删除控制流叙述与代码复述。
- **模块注释：** 说明模块的角色、依赖、职责与非显然的架构选择；把架构选择链接到拥有其解释的地方。
- **测试：** 只解释非显然的测试设计——某个 fixture、断言、平台适配、真实入口路径或间接观察为何必要。删除走查与清单。
- **操作手册（cookbook）：** 包含前置条件、必需动作、真实入口路径、可观察校验与简短警告。
- **README:** 包含消费方契约：配置、语义、失败、限制、扩展点与面向模型的效果。引用由该包拥有的、稳定的面向模型文本；链接生成的目录与跨包所有者。保留持久缺口与维护者陷阱，而不是普通的清理清单。遵循包 README 的要求。
- **Agent Note:** 保留独特的理由、机制、替代方案、后果、已交付的校验证据与具名覆盖缺口。已实施的 Agent Note 用现在时陈述已交付的现实；删除规划清单，而不是保留「钉住该决策的是什么」的证据。
- **事故复盘：** 保留事故序列、证据、因果链、影响与预防。删除反复的说服或与确立因果关系无关的实现细节。
- **技能与 agent 指令：** 陈述行为护栏与显式的范围限制，例如「这是指引，不是脚本/检查清单」。保持工作流简短，并链接其真相来源。
- **示例与配置注释：** 解释访问限制、非显然的接线或加载顺序、安全立场、回放行为、例外与可能的误用。不要叙述配置本身已经展示的条目。
- **提示词与可见字符串：** 把措辞当作行为。用户可见文案属于有类型的 locale 字典，经显式本地化 prop 抵达与框架无关的原语；文本、无障碍名称、tooltip、placeholder 与格式模板要一起检查，再运行仓库自己的本地化门禁。面向模型的文本更新其所属的可运行快照，并补齐仓库要求的证据。若授权范围内没有所属场景，保持措辞不变并报告推迟；不要悄悄把它并入纯散文编辑。
- **诊断：** 点明失败的主体或路径、被违反的规则，以及不显然时的纠正方式。删除内部执行叙述。

保留可搜索的机制名，以及有意义的模态、时间或否定强调。只统一装饰性强调。

<a id="workflow"></a>

## 工作流

1. 确认范围、模式、当前分支或 PR 基线，以及适用的 `AGENTS.md`。不要检查无关分支。
2. 判断某段之前，先读[文档标准](../../../Docs/AGENTS.md)与拥有该内容的代码或文档。需要校准或遇到陌生情形时，读[提炼后的示例](references/examples.md)。
3. 检查请求的范围，而不只是最大的文件。用搜索与词数找出候选，再按语义判断段落。
4. 把每个候选归类为保留、补充、精简、恢复、重构或推迟。只有任务授权编辑时才施加明确改动；不要为满足删除指标而制造改动。
5. 先更新所有者，再更新派生物。学到新规则后，重新检查同类段落。
6. 运行窄范围的相关检查、文档门禁、`git diff --check`，以及针对可见字符串的行为测试。核实最终 diff 不含 `vendor/` 路径；若意外命中 vendor，报告它，而不要宣称排除历史干净。
7. 报告检查过的范围、明确改动、有意保留、推迟的情形，以及实际运行的检查。

<a id="borderline-decisions"></a>

## 边界情形

只有当至少两个版本都满足完整命题规则、却在不同既定原则之间取舍，且本技能尚未裁定该取舍时，才算边界情形。若改写只有一个保命题答案，就不是边界情形。

在自动模式下，获授权时直接施加明确编辑，并报告真正的边界情形而不提问。不要为推进进度而弱化命题。

在交互模式下，按主导原则把同类段落分组。给出两到三个可行版本，推荐其一，并说明事实或结构上的差异。不要提供更差的干扰项。使用用户要求的渠道；通过行内评论校准 PR 时，把推荐的暂定版本放进 diff，并把备选方案挂到该确切行。

用户决定后，把原则与版本提炼进[示例](references/examples.md)，不要带上 PR 历史或评审者叙述，并把学到的规则应用到范围内每个同类段落。
